## Declarative and imperative knowledge

> Knowledge can be divided into declarative statements of fact and imperative descriptions of how to deduce or find something. A square-root procedure attributed to Heron of Alexandria illustrates how imperative knowledge provides a repeatable computational method.

### Declarative knowledge

Declarative knowledge consists of assertions of truth, definitions, or axioms. The definition of the square root of x is the positive y such that y² = x. This definition allows a proposed answer to be tested, but it does not provide a method for finding the answer.

For x = 2, the square-root definition can test whether a candidate value has a square close to 2, but it does not explain how to obtain the candidate.

### Imperative knowledge

Imperative knowledge is a recipe: a sequence of specific instructions performed in order. An imperative procedure can include tests that affect what happens next and an end condition that identifies when the procedure is complete and supplies the answer.

**Computational character**

> The procedure is computational because it specifies ordered actions, conditional testing, iteration, and a termination rule.

### Square-root procedure

1. Start with a guess g.
2. If g² is close to x, stop and return g.
3. Otherwise, replace the guess with the average of g and x/g.
4. Repeat the test and update steps until the stopping condition is met.

**Guess update**

```latex
g \leftarrow \frac{g+x/g}{2}
```

The update replaces the current guess with the average of g and x/g.

To approximate the square root of a value x, repeatedly compute (g + x/g)/2 from an initial guess g until g² is sufficiently close to x. This square-root procedure is attributed to Heron of Alexandria.

## Computer architecture and execution of stored programs

> A stored-program computer represents instructions as data in memory and uses hardware components to execute primitive operations, normally advancing the program counter and occasionally redirecting it to create the flow of control.

### From fixed-purpose circuits to general computation

A computation can be implemented as a mechanical circuit containing storage, connections, arithmetic operations, and tests. For example, a circuit for a square-root procedure could include stored values, wires to move values, addition and division units, and a testing component.

**Fixed-program and general computers**

- Early fixed-program computers had circuitry designed for a specific computation and performed only that computation.
- A calculator is a fixed-program computer designed for arithmetic rather than general tasks such as video games or word processing.
- An early computational device designed by Atanasoff in 1941 is identified as solving linear equations; fixed-program computers could solve only the equations or specific problems for which they were built.
- Alan Turing’s bombe was an early fixed-purpose computer designed to break German Enigma codes during World War II.
- A more capable machine would accept a description of another computation and behave like the described calculator, code-breaking machine, or square-root machine.

### Recipes, interpreters, and stored programs

A machine that accepts a recipe—a description of a sequence of steps—and then acts according to that recipe is called an interpreter. This idea produces a stored-program computer: instructions describing a process are supplied to the computer and executed as specified.

**Stored-program principle**

- The instruction sequence is stored in memory alongside data and is treated like data.
- Instructions can be accessed, changed, used to build new code, and interpreted.
- The central idea is to construct descriptions or recipes from primitive instructions and control how those instructions are traversed.

### Components and execution

**Basic components**

- Memory stores the instruction sequence and values.
- The control unit processes instructions.
- The arithmetic logic unit (ALU) performs simple operations on values taken from memory and places results back in memory.
- Input and output support communication with the computer.
- The program counter points to a location in memory, typically the first instruction in the sequence.

**Instruction execution and control flow**

1. An instruction directs the machine to retrieve values from memory, perform a simple operation such as multiplication, and store the result in memory.
2. After the instruction is executed, the program counter normally advances to the next instruction.
3. Some instructions test whether a condition is true.
4. When the condition is true, the instruction changes the program counter to another location in memory.
5. Sequential movement, with occasional changes in location, creates the flow of control.
6. Execution ideally eventually stops and produces an output value.

## Programs, primitives, and computational universality

> A program is a recipe: a sequence of primitive instructions that describes a computation and its control flow. Primitive operations can be combined into meaningful expressions and instruction sequences, then abstracted as new primitives. Turing showed that six simple primitives can express any mechanically describable process, while modern languages provide more convenient abstractions with the same fundamental computational power.

### Programs as recipes

A program is characterized as a recipe: a sequence of primitive instructions that describes a computation. Computation involves describing recipes and the control flow through them. A traditional recipe uses a small set of primitives that a skilled cook can combine into an unbounded number of dishes; programming follows the same principle by combining a fixed set of programming primitives to express any process that can be described algorithmically.

### Turing compatibility

Alan Turing showed in 1936 that six simple primitives can express any mechanically describable process. Turing's six primitives operate at a very low level, such as transferring a value to a tape. The fundamental idea is that a suitable set of primitives can express any mechanically describable computation.

This result implies that anything expressible in one Turing-compatible programming language is expressible in another. It does not mean that all languages are equally good for every task: languages can differ in convenience and suitability for particular kinds of problems.

### Abstraction and the study of Python

Programming directly with operations such as moving values on a tape would be unnecessarily painful. Modern programming languages therefore provide higher-level abstractions and broader, more convenient sets of primitives while preserving the same fundamental computational power. Higher-level abstractions let programmers describe computational recipes without manipulating machine-level storage directly.

Programming involves breaking problems into computational steps and expressing those steps legally in a language that can interact with a computer. Doing this requires identifying the language's primitives, knowing how to combine them legally, and communicating with the computer.

Python is introduced as the setting for beginning this study of computation. The immediate focus is on simple parts of Python, with further development deferred to later instruction. Expressions are built from primitive data elements called values.

**Course goal**

The course goal is to combine primitive operations into complex expressions, abstract those expressions as new primitives, and use instruction sequences and control flow to derive new information.

## Programming-language selection and implementation

> There is no universally best programming language. The appropriate choice depends on the problem, including the language’s primitive operations, intended application range, level of abstraction, and execution method. The course uses Python primarily as a medium for learning how to design and structure computational recipes; these conceptual tools can transfer to other languages.

### Choosing a language for the problem

Languages have different strengths and weaknesses, so language selection depends on the problem being solved. The course selects Python as a useful medium for learning programming concepts, not because it is universally superior.

- MATLAB is well suited to vectors, matrices, and computations naturally represented in that framework, but other tasks can be difficult in it.
- C is useful for programming systems such as those controlling data networks.
- Lisp and Scheme are well suited to problems involving arbitrarily structured data sets.
- A general-purpose language provides primitives supporting a broad range of applications; a targeted language is designed for a specific application area.
- MATLAB is presented as a targeted language aimed at matrices, vectors, and related computations.

### Python as a course medium

The course uses Python to teach how to design and structure computational recipes. The transferable goal is learning how to think about and organize programs rather than mastering Python-specific syntax. Students need enough Python to use it effectively, but the course is not centered on syntactic details such as punctuation rules.

- The intended takeaways include designing recipes, structuring recipes, and using programming modes in Python.
- The lecture claims that these conceptual tools transfer readily to other languages, making it possible to learn another language relatively quickly after learning Python.
- Python is a relatively new and increasingly popular language that incorporates features from earlier languages.
- Python is better suited to manipulating strings than numbers in some respects, but it remains a general-purpose language.

### Comparing language levels

One dimension for comparing languages is their level: how closely their primitives correspond to the internal operations of the machine. A low-level language, such as assembly programming, works close to the machine and may use primitives that move data between memory locations. A high-level language provides abstractions designed to express computations farther from the machine’s internal details.

A high-level language may provide richer primitives, such as a built-in square-root operation, instead of requiring the programmer to implement the operation. This introduces trade-offs.

### Interpreted and compiled execution

- Interpreted language: Operates on source code at run time through an interpreter that controls the execution of instructions and produces output.
- Compiled language: First processes source code through a checker or compiler to create object code before execution.
- Compilation can catch bugs before execution and often transform the program into a more efficient sequence of instructions.
- Interpreted languages are often easier to debug because the programmer can inspect the raw code during execution, but they are not always as fast.
- Compiled languages are usually faster during execution, so the choice involves a trade-off between debugging convenience and execution speed.

Python is described as a high-level, general-purpose, primarily interpreted language. Because Python is interpreted, it is not as effective at catching certain problems before execution, while it can support debugging during execution.

## Syntax, semantics, and programming errors

> Syntax specifies which expressions are legally formed. Semantics concerns meaning: static semantics asks whether syntactically valid code is meaningful, while full semantics concerns what happens when the program runs. Syntax and some static-semantic errors can be detected automatically, but many semantic bugs remain executable and may produce unintended results.

### Syntax and meaning

Programming languages define how components may be assembled into legal expressions. An expression can be syntactically invalid even when it contains recognizable words or symbols, just as a sequence of nouns may fail to form a grammatical English sentence. A syntax error occurs when the written form of an expression does not conform to Python’s syntax.

**Three related concepts**

- Syntax: whether an expression is legally formed in the language.
- Static semantics: whether a syntactically valid program or expression makes sense.
- Full semantics: what the program means or what happens when it runs.

An English sentence can be grammatically correct but meaningless, illustrating the distinction between syntax and static semantics. Similarly, a syntactically correct program with apparently correct static semantics may produce the correct result, crash, run indefinitely, or appear to produce the correct result while being wrong.

### Checking errors and unintended behavior

Python provides built-in assistance for checking syntax and generally reports one syntax error at a time, indicating where the invalid syntax originated so it can be corrected. The lecture explicitly states that submitted work that is not syntactically correct receives a zero, despite the system providing a syntax checker.

- Static checks catch some errors before execution, and errors caught this way are often relatively easy to diagnose because the program cannot run with them present.
- Languages differ in how much help they provide with static-semantic errors; in Python, such checking occurs at run time according to the lecture.
- Most available checks occur at runtime rather than before execution, delaying detection until the code is run.
- Static semantics does not catch every problem. A program may produce an unintended value, and the error can propagate through many computations before causing a major failure.
- It is not generally possible to determine automatically whether a computation is stuck in an infinite loop or merely taking a long time.
- Because semantic bugs are difficult to detect automatically, programmers need a style that makes likely sources of such bugs easier to identify.

### Operand types and operator meanings

Operations must be compatible with their operand types. In the arithmetic case, multiplication expects arithmetic-compatible operands, so attempting to multiply two strings produces a static semantic error. Python nevertheless permits multiplying a string by an integer, assigning multiplication a different meaning for that type combination: the string is repeated that many times.

## Python values, expressions, operations, and assignment

> Python works with values such as numbers and strings. The type of a value determines which operations accept it and what results they produce. Expressions evaluate to values, commands or statements request actions, and assignment binds names to values for later reference.

### Values and types

Python begins with numbers and strings as primitive data elements. A string is written with an opening quote, a sequence of characters, and a closing quote; it may contain spaces and other characters. Numbers include integers (INTs) and floating-point values (floats), which can be viewed as real numbers.

**Quoted text and numbers**

- "52" is a string because quotation marks surround the digit sequence.
- 52 is a number because it is not quoted.
- Putting quotation marks around text makes Python return the string itself rather than evaluate the text inside it as an arithmetic expression.

**Different values in Python**

```python
"52"  # a string
52    # a number
```

The quoted digit sequence and the unquoted number are different values.

### Expressions, statements, and the interpreter

The Python interpreter evaluates expressions and returns their values. An expression is something for which the interpreter computes a value. A command or statement instead uses a value to ask the computer to perform an action. In the Python shell, entering a number returns a number, and entering a string returns that string.

**Expression and command**

- An expression produces a value directly.
- The print command obtains an expression’s value and displays it.
- Python visually distinguishes print from an expression evaluated for its value.

**Expression structure**

```python
52
"52"
operand operator operand
```

Simple arithmetic uses an operand-operator-operand structure.

**Quoted arithmetic text**

```python
"52 * 7"
```

This produces the string 52 * 7, not the result of multiplying 52 by 7.

### Arithmetic operations and division

Python supports arithmetic operations including addition, multiplication, exponentiation, and division. Exponentiation uses the double-asterisk operator. Division behavior depends on the operand types: integer division discards the fractional part and retains the remainder relationship, while using a float produces real-valued division.

**Arithmetic operations**

```python
3 ** 5
3 / 5
3.0 / 5
```

The first expression computes a power; the lecture describes integer division as 0 with remainder 3 and floating-point division as approximately 0.6.

**Division types**

### String operations

Strings can be printed and can also be used in operations. Adding strings merges their contents into one string, and multiplying a string by an integer repeats the string. Strings also have operations such as length and addition, which students will explore later.

**Joining strings**

```python

```

Adding the strings merges their contents into one string.

### Assignment and names

Assignment binds a name to the value of an expression. A statement such as mystring = ... creates the variable name mystring and binds it to the following expression’s value. After assignment, evaluating mystring retrieves the stored value. A stored string can be combined with another string and printed.

**Binding and using a name**

The assignment stores a string under mystring; later expressions can refer to and combine that value.
